# 抖音 / B站链接转存

Aurabot 用户扩展。主人发来一条**抖音**或**B站**链接，她把里面的**视频**或**图集**取下来，直接发回 QQ——视频走视频消息，图集一张张发图片。主人明确要的时候，还能把视频**转成文字稿**、把**评论**读出来。

解析用本机的 [DouYinDownload](../../README.md)（`dtk`）MCP，下载和发送都在插件这边做。

只给主人私聊（「完整」权限）用。群聊、别人私聊里没有这个工具。

## 支持哪些链接

| 平台 | 认得的写法 |
|---|---|
| 抖音 | `douyin.com/video/…`、`douyin.com/note/…`（图集）、`v.douyin.com/…` 短链、`modal_id=…` |
| B站 | `bilibili.com/video/BV…`、`/video/av…`、`m.bilibili.com/…`、`b23.tv/…` 短链、`bili2233.cn/…` 短链 |

主页、直播间、合集不是单个作品，会被明确拒掉（会告诉你是哪种）。TikTok 还没接。

## 它怎么工作

```
QQ 链接 → douyin_save → dtk MCP parse_url（认出平台、作品类型 + 媒体地址）
        → 视频：按平台带 Referer 下载到 QQ 工作区 → OneBot video 段（单独成条）
        → 图集：逐张下载 → webp 转 jpg → 当图片发
        → 临时文件清掉
```

媒体只走本机到 QQ，**不进模型上下文**：36 MB 的视频对 token 的消耗是 0，模型只看到一句「视频发出去了」。

要文字稿 / 评论时走另一条：

```
QQ 链接 → parse_url → download_media（服务端存一份，同一个作品复用）
        → transcribe_video（本机 FunASR，5 分钟视频约 10 秒）→ 文字稿发回 QQ
        → 或 list_comments（带点赞数）→ 前 N 条热评发回 QQ
```

## 三种触发方式

**默认只发媒体。** 读稿、读评论要主人明说，或者敲命令——她不会自己给你加戏。

| 你做什么 | 她做什么 |
|---|---|
| 发一条抖音链接（说要「下载」「发我」） | 只发视频 / 图集 |
| 「转写一下」「文字稿」「这条讲了什么」「总结一下」 | 发文字稿 |
| 「看看评论」「热评说啥」 | 发前 N 条评论 |
| `/dy <链接>` | 直接转存，不经过模型判断 |
| `/dy 转写 <链接>` | 直接转写，不经过模型判断 |
| `/dy 评论 <链接>` | 直接读评论，不经过模型判断 |

命令是 100% 确定的；「明说」那两条靠工具描述和提示词约束（扩展工具按会话挂载，拿不到单条消息原文，做不到逐条硬闸）。面板里「允许她自己判断读稿 / 读评论」**默认关**，关着时工具描述写死「只有主人明确要求时才用」。

「收到链接就自动发」开着时也照顾这两种请求：消息里带「转写 / 文字稿 / 讲了什么 / 评论」这类词，自动转存会让路，把这条交给她按你说的做，不会只发个视频就完事。

## 按需启停（省内存）

下载服务整套（WSL + 6 个容器）闲着也要占 2~3 GB，所以默认不常开：

- **用的时候自动起**：服务没在跑时，发链接 / 要转写 / 要评论都会先自动 `dtk start`，等 `/readyz` 就绪再干活。冷启动一般 20~60 秒（WSL 刚开机要起容器），期间她会先发一条「正在启动」的日志。
- **闲着自动关**：上一次用完之后计时，默认 **30 分钟**没人用就 `dtk stop`，WSL 虚拟机一起关掉。再要用会重新起。
- **不会打断正在干的活**：正在处理请求、或者服务端还有下载在跑（`in_flight` / 队列非空）时会自动顺延，不会把转写/下载掐断。

面板「扩展 → 抖音链接转存」里两项可调：「服务没开就自动启动」（默认开）、「空闲多久自动关闭服务」（默认 30 分钟，`0` = 一直开着）。

文字稿太长（默认超过 6000 字）不会糊一屏，改成发一个 `.txt` 文件，聊天里留一段开头。

## 需要什么

- Aurabot（扩展接口 1），主人私聊是「完整」权限
- 本机装好 [DouYinDownload](https://github.com/Evil0ctal/Douyin_TikTok_Download_API) 的 `dtk`，并且服务在跑（`dtk start`，或直接 `dtk dl <链接>` 它会自己拉起来）
- `ffmpeg` 在 PATH 里（图集的 webp 要转 jpg；没有就原样发 webp，QQ 不一定认）
- 转写要服务端开着 `transcriber`（本机已启用；`/api/v1/system/status` 里 `transcriber.ok` 为 true 就是好的）

## 安装

从本 repo 的 `extensions/douyin-save` 目录：

```sh
npm run install:module
```

默认装到 `~/.dsh/plugins-data/aurabot/modules/douyin-save`，遵守 `DSH_HOME`、`AURABOT_DATA_DIR`；也可以指定目标：

```sh
npm run install:module -- "D:/my-data/aurabot/modules/douyin-save"
```

没有依赖、不用构建。装好后 Aurabot 几秒内自动热重载，面板「扩展」页能看到它。

## 设置

面板「扩展 → 抖音链接转存」：

| 项 | 默认 | 说明 |
|---|---|---|
| MCP 地址 | `http://127.0.0.1:8000/mcp/` | 末尾斜杠要保留 |
| API Key | 空 | 留空时自动找：账号文件 → `dtk where` 指的项目目录里的 `console-account.txt` |
| 账号文件 | 空 | 想手动指定 `console-account.txt` 时填 |
| 收到链接就自动发 | 关 | 开着时，主人私聊里出现抖音链接就直接发，**她不再走正常回复**（只发媒体，不读稿不读评论；要转写 / 评论的消息会自动让路） |
| 视频怎么发 | 视频消息 | 发不了会自动改成当文件发 |
| 图集最多发几张 | 9 | 长图集只发前几张 |
| 视频大小上限 | 200 MB | 超过就不发，回一句提示 |
| ffmpeg 路径 | `ffmpeg` | 留空用 PATH 里的 |
| 允许她自己判断读稿 / 读评论 | 关 | 关着 = 只有主人明说或敲 `/dy 转写` 才做 |
| 文字稿多少字以内直接发 | 6000 | 超过就当 txt 文件发 |
| 读几条评论 | 10 | 最多 30 |
| 服务没开就自动启动 | 开 | 关掉后服务没运行时会直接说「先跑 dtk start」 |
| 空闲多久自动关闭服务 | 30 分钟 | `0` = 一直开着；关掉能省 WSL 那 2~3 GB |

## 已知边界

- **短链偶尔展不开**：dtk 会回一句 `retryable`，扩展隔 1.2 秒自动重试一次，再不行才报错
- **主页 / 直播 / 合集**：`parse_url` 认得出但不是作品，会回「这是作者主页，不是单个作品」或「没解析出这个作品」
- **B站 老视频可能没播放地址**：`media.video.urls` 为空时（老视频、充电专属、要登录才能看的）会回「没取到 B 站的播放地址」，不会瞎发一个空文件
- **B站 多 P**：按链接指向的那一 P 发；一条里有多 P 时，成功提示后面会带「（多 P 视频，共 N P）」，方便你知道发的不是全部
- **图集不能转写**：没有声音，直接回「这是图集，没有声音可以转」
- **转写要几十秒**：得先把视频存到服务端再跑 ASR（4 分钟视频实测 12 秒；长视频更久）。期间会先发一条「稍等」的提示
- **转写排队**：服务端单次工具调用上限 60 秒，超了会回 `pending`，扩展用 `get_task_result` 接着等，不会重复排队
- **视频当文件发**：QQ 视频消息这条路失败时的兜底，受面板「发文件」的目录和大小限制（默认 50 MB）
- **图集是 webp**：抖音图集基本都返回 webp，靠 ffmpeg 转 jpg；转失败就原样发
- **B站 下载走 CDN 直链**：本机代理卡顿时会超时，和 `dtk` 自己的下载一个毛病，重试即可
- **服务是关着的时候第一次用会慢一点**：要等 WSL 和容器起来（冷启动 20~60 秒），之后就在空闲窗口内一直开着
- **服务起不来**：她会回「终端里跑一下 dtk start 看看报什么错」，不会卡在那儿等

## 安全

- API Key 只在本机读、只发给 `mcpUrl`，不进日志、不进模型上下文
- 下载的媒体落在 QQ 工作区临时目录（`_douyin_tmp/`），发完即删
- 转写产生的服务端副本落在 dtk 的媒体卷里，受它自己的容量上限管（默认 2 GiB，超了淘汰最旧的）
- 只有主人私聊能用；群聊里没有这个工具
